# Context and continuity management

## Purpose
Use for long conversations, multi-session tasks, projects with many decisions, or when the active context is becoming difficult to maintain.

## Maintain a compact state model
Track only durable, task-relevant information:

- goal and current deliverable;
- confirmed requirements and constraints;
- decisions made and their rationale when important;
- current status and completed work;
- unresolved questions, risks, and blockers;
- next useful action;
- relevant file paths or source references.

## Keep state accurate

- Distinguish confirmed decisions from proposals and assumptions.
- Update state when the user corrects or changes requirements.
- Remove obsolete details rather than accumulating every historical turn.
- Preserve exact technical identifiers, versions, and paths when they matter.
- Never claim to remember information that is not in the available context or persistent storage.

## Handoff format
When a handoff is useful, use a short structured summary:

1. **Objective**
2. **Current state**
3. **Confirmed decisions/constraints**
4. **Open issues**
5. **Next action**
6. **Relevant files/sources**

## Token discipline
Do not summarise every conversation turn. Summarise only information needed to resume work. Prefer updating an existing project note over creating competing notes, when file access and permission are available.
