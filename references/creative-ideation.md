# Creative ideation and brainstorming

## Purpose
Use when the user wants new ideas, brainstorming, creative alternatives, concept development, or ways to improve an existing idea.

## Identify the creative stage
Determine whether the user is:

- exploring a blank space;
- generating options;
- expanding an existing concept;
- escaping a creative block;
- combining or transforming ideas;
- selecting or narrowing options;
- refining a selected concept;
- planning a first experiment.

Do not run the entire pipeline when the user only needs one stage.

## Understand the brief
Use available context to identify purpose, audience, problem, constraints, resources, differentiation needs, and desired level of novelty. Clarify only if a missing detail materially changes the direction.

## Diverge before converging

- During exploration, generate varied possibilities and avoid premature rejection.
- When narrowing is requested, evaluate fit, distinctiveness, feasibility, risks, and cost.
- When the user has selected a direction, develop it rather than endlessly producing alternatives.
- Use creativity methods (first principles, analogy, SCAMPER, constraint reversal, premortem, or others) only when they help; do not force a named framework into every task.

## Make ideas concrete
A useful idea should explain, as appropriate:

1. Who it is for and what problem or desire it addresses.
2. What it actually does and how the mechanism works.
3. What makes it different from familiar alternatives.
4. What resources or prerequisites it needs.
5. Its main weakness, failure mode, or trade-off.
6. The smallest realistic first test or implementation step.

Avoid generic buzzword combinations, vague “AI-powered” claims, feature lists without a user problem, fake precision, and novelty that exists only in wording.

## Quality control

- Compare against known products or ideas only when there is evidence; research current competitors if uniqueness claims matter.
- Do not claim an idea is original or unprecedented without a sufficiently broad search.
- Prefer a few developed, context-specific concepts over a large generic list.
- Keep feasibility as a dimension, not a gate that kills early exploration. A high-risk idea may be worth retaining as a speculative direction if labelled honestly.
- When evaluating, identify the strongest differentiator and the most serious weakness.

## Good collaboration
Ask whether the user wants breadth, depth, critique, selection, or implementation when their desired stage is genuinely unclear. Otherwise infer the stage from the request and proceed.
